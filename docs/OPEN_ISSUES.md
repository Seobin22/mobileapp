## 문서와의 차이(확인 필요)
- **v3 block_started 트리거(문서에 없음)**: §6 프롬프트는 "작업이 시작되면 체크인 예약"을 요구하지만 §2 트리거 표에는 블록 시작이 없다. [시작]을 누르면 비서가 깨어날 계기가 없어 `block_started` turn 을 추가했다(블록 수만큼 turn·비용이 는다).
- **v3 first_unlock 수집 한계**: 안드로이드는 잠금 해제(USER_PRESENT)를 앱이 살아 있을 때만 받는다. 앱이 종료돼 있으면 그날은 기상+60분 fallback 으로 아침 브리핑을 한다.
- **v3 협상 → v3.1 풀스크린 대화**: 답은 FCM 으로 오고, 앱도 3초마다 서버를 확인한다. 대화 시간 뒤 재등장은 FCM 과 별개로 앱이 서버 상태를 물어서도 처리한다.
- **v3.1 고정 블록 화면 문구**: 개정 문서(§3.2)대로 비서가 screen_text 를 정하고, 비어 있으면 lead>0 "곧 {title}이에요. {lead}분 뒤 시작", 0 "지금 {title} 시간이에요".
- **v3.1 고정 블록의 수면·방해 금지 검사(문서에 없음)**: 사용자가 정한 시각이라 검사하지 않는다. 수면·방해 금지 시간이면 알람이 안 뜨므로 도구 결과에 warning 을 주고 비서가 알린다. v1 호환 `/v1/admin/tasks` 는 계속 거절한다.
- **v3.1 계획 블록 수정(문서 §4.1 "수정 후 비서에게 알림")**: 계획 블록을 직접 고치는 API 가 문서에 없다. 앱에서 길게 누르면 요청을 채팅으로 비서에게 보내고 비서가 다시 배치한다.
- **v3.1 DB·백업(§2.1)**: DB 는 이미 파일 H2 라 PostgreSQL 전환은 하지 않았다. 매일 백업은 서버 cron 대신 앱 작업(04:00, 7일 보관). 백업 파일은 서버 디스크(`/root/data/assistant/backups/`)에만 있어 서버 디스크가 통째로 사라지면 같이 없어진다(외부 보관은 별도 결정 필요).
- **v3.1 문서 전제 "앱 3.0.1"**: 실제로는 3.0.2(Firebase 연결)에서 3.1.0 으로 올렸다.
- **v3.1 준비 시간 '누가 정했나'(문서에 없는 세부)**: 비서가 도구로 넣은 값은 assistant 로 기록되는데, 사용자가 채팅에서 "20분 전에 알려줘"처럼 직접 말한 값은 비서가 prep_from_user=true 로 표시해야 user 가 된다(표시를 빠뜨리면 나중에 비서가 바꿀 수 있다). 앱에서 넣은 값은 항상 user.
- **v3.1 목표 누락 검사 범위**: turn 끝 검사는 그 turn 에서 손댄 목표만 본다(손대지 않은 다른 목표까지 막으면 관련 없는 대화가 끝나지 않는다). 나머지는 이어 잡기·아침·저녁 점검이 맡는다.
- 문서 §3·§9(v1)·§2.1(v2)의 Python/Docker/별도 프로세스 대신 Spring 앱 안에 구현했다(사용자 선택). 같은 동작을 스레드 두 개로 보장한다.
- v2 §8.2 의 max_tokens=2000 은 Sonnet 5.5(thinking 항상 켜짐)에서 응답이 잘릴 수 있어 8000 으로 했다.
- v2 §1 "AGENT_MODEL 이 비면 서버 시작 시 에러로 멈춘다" — 같은 서버에 파일 전송·개입 기능이 함께 있어, 멈추지 않고 채팅만 비활성화했다.
- v1 §6.6 "nudging → 아무것도 안 함"과 §6.4 expire 사이: 블록 끝 + 15분 유예 동안 개입이 계속된다. 의도대로 구현했다.

- **v3.2 §0-2 "준비 시간 기본값(`fixed.default_lead_minutes`)은 그대로"**: 이 설정은 v3.1 개정 3에서 이미 없앴다(V6). 지금 상태(기본값 없음, 비서가 판단)를 유지했다.
- **v3.2 평가 세트 "다음 날 같은 내용 반복 안 함"**: 평가기는 turn 하나만 돌려 하루 뒤를 이어서 볼 수 없다. 전날 고지 기록을 넣은 별도 케이스(`evals/v3_2/07`)로 나눴다.
- **v3.2 배포 재시작**: master push 마다 서버가 재시작되어, 처리 중이던 turn 은 "interrupted by restart" 로 끝나고 다시 시도되지 않는다(2026-11-02 무응답 원인). v3.2 범위가 아니라 고치지 않았다.
